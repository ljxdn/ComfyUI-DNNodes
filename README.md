# ComfyUI-DNNodes

给 **MiniMax H3** 视频工作流用的五个 ComfyUI 自定义节点：把「一张资产卡（图 / 音 / 描述）」
直接喂给导演台的分段（r2v 分组），需要时再把分组拆回逐个素材口去接官方工作流，
多段还能交给「资产卡任务台」按顺序一段段跑，另有一个自带一采 / 二采缓存路由的
「SelfLift Sampler DN」，
并附带一整套顺手的编辑体验（单端口多连线、选中高亮上游、提示词富文本编辑器）。

![DN 节点效果展示](<assets/DNnodes效果展示.jpg>)

## 节点

| 节点 | 节点 id | 作用 |
|---|---|---|
| **资产卡** | `H3MediaLoader` | 一张资产：图像（可粘贴截图 / 拖放 / 输入目录下拉）+ 音频（波形、播放、裁剪、静音）+ 资产描述；另有「资产名」「最长边」。输出 `media / image / audio / prompt` |
| **资产卡镜头打包** | `DNMediaToDirectorGroup` | 把若干张资产卡打包成 **MiniMax H3 Director** 的 Reference-to-Video 分组（`MMX_DIR_GROUP`），可直接接导演台或 `Groups Combine` |
| **资产卡Group拆分** | `DNGroupSplit` | 反过来：把一个 `MMX_DIR_GROUP` 拆回**逐个素材口**（`image_1..9` / `video_1..3` / `audio_1..3`）+ 最下方一个 `prompt` 文本口，用于接 **MiniMax H3 官方工作流** 的逐口接线方式 |
| **资产卡任务台** | `DNGroupDirector` | 把**多段**「资产卡镜头打包」汇到一个节点（段数不限），按面板顺序**一段段依次跑**，下游「拆分 → 参考生成 → 采样」只接一次线<br>（原「资产卡导演台」，2026-10-15 改名，节点 id 不变） |
| **SelfLift Sampler DN** | `DNSSelfLiftH3` | SelfLift 渐进采样的封装：**一采（低分辨率前缀）/ 二采（提升 + 全分辨率收尾）可以分开跑**，一采结果按指纹落盘缓存，下次同参数**跳过一采**直接收尾。依赖兄弟包 [`comfyui-SelfLift`](https://github.com/facok/comfyui-SelfLift)（缺失时本节点不注册，其余四个照常可用） |

`medias` 端口可**接多条连线**（最多 9 条），编号顺序 = 连线顺序 = 提示词里
`<Picture N>` / `<Audio J>` 的编号。拆分组出来的口顺序与编号一致：
图片在前、视频其次、音频在后，`prompt` 在最下面。

## 安装

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/ljxdn/ComfyUI-DNNodes.git
```

重启 ComfyUI。依赖：ComfyUI 本体自带的 `torch` / `numpy` / `Pillow`，**无需额外 pip 包**。

想用第二个节点的输出，需要另外安装
[ComfyUI_MiniMaxH3_Director](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director)（Apache-2.0）。

## 功能

### 资产卡

- **图像**：输入目录下拉 / 拖放 / 截屏后**一键粘贴**（图片区右上角剪贴板按钮，或鼠标停在图片区按 `Ctrl+V`）；
  同内容重复上传按 MD5 去重，不会堆文件。
- **音频**：波形上拖选区间 → `裁剪` 写回 `trim_start` / `trim_end` / `还原`；`静音` 时输出 `audio = None`。
- **最长边**：参考图最长边超过该值即等比缩小（只缩不放），默认 1440。
- **资产名**：参与「提示词里没提到的资产会被跳过」这一过滤规则；
  同时会以**大号字体（20px，比节点标题大一号）显示在节点标题栏下方**那一行空白里 ——
  左对齐、超长自动 `…` 截断，卡片一多也能一眼认出谁是谁。
- **默认尺寸 320 × 480**：宽 320（最小可拖到 300），高 480。
  宽高都是照实机手调值取的整（原默认宽 480 太占地方）——
  注意高 480 其实是布局公式 `DEFAULT_HEIGHT` 算出来的结果，和手调值正好吻合，所以没写死。

### 资产卡镜头打包

- **单端口多连线**：往 `medias` 拖第 2 条线时，自动把你原本那条也收编进来，一张都不丢；
  点一下线中点的圆点即可「**本段不带音 / 本段带音（恢复）** / 序号提前 / 序号退后 /
  删除这条连线 / **替换这张卡…**」，节点右键菜单可「清空全部连线 / 连线顺序反转」。
- **段级音频开关**：卡片自己勾静音（`audio_muted`）是**卡级**的 —— 同一张卡被多个段引用时
  一勾全没。右键连线圆点的「本段不带音」只关**当前这个节点这一段**的音，图照送、编号不变
  （圆点变琥珀色示意）；同一张卡 A 段带音、B 段不带音互不影响。
  实现：连线记录里只写 `skip_audio` 标记，注入 prompt 时按连线顺序拼成 `link_audio_mask`
  （如 `"101"`），后端在**角色过滤之前**按位摘音 —— 缺位一律按「带音」处理，老工作流零影响。
- **音频超 3 条不炸节点**：MiniMax H3 只收 `<Audio 1>…<Audio 3>`，以前第 4 条音直接 `ValueError`
  整个节点跑不了；现在改为**截断保留前 3 条**（按连线顺序），其余丢弃，
  并在 ComfyUI 控制台打印一条人话说明（截了几条、怎么腾位置）。参考图超 9 张仍保持报错
  （那属于接线错误）。
- **圆点数字 = 实际编号**：显示的是这张卡在后端真正占的 `<Picture N>` / `<Audio J>`；
  被跳过的卡（资产名没写进提示词）**不吃号、也不画数字** —— 圆点上的数字永远等于喂进模型的编号。
- **被跳过的卡会显形**：后端只收「资产名出现在提示词里」的卡（与上游同一规则）；
  这些卡在画布上画成**灰色虚线 + 灰点**，选中时它们的金圈也变灰圈，
  同时编辑框上方出现一条琥珀色提示条列出是哪几张 —— 不再有"连了却没生效"的黑盒。
- **提示词空着 = 一张都没引用**：一个字都没写时，带资产名的卡全部按**未引用**画
  （灰色虚线 + 不画数字），而不是像以前那样配着 3 条绿线 1/2/3 假装已生效 ——
  这和后端一致（此时后端 `role_name not in ""` 恒真，一张都不会收）。
  把资产名写进提示词，对应的卡立刻变回绿线并拿到编号。
- **选中即高亮上游**：选中该节点时，它这一段真正吃进去的卡与中间节点会亮起琥珀金，
  一眼看清「这条用了哪几张卡」。
- **反过来也认（选中资产卡 → 高亮下游）**：选中任意**资产卡**时，用到它的那些
  「资产卡镜头打包」节点会连同连线一起点亮，一眼看清「这张卡被哪几段用了」。
  颜色刻意换成 **`H3_MEDIA` 连线本身的颜色**（本包画虚拟连线用的同一个取色口，
  `LGraphCanvas.link_type_colors.H3_MEDIA`，缺失时回落 `#34d399`）——
  和"选组时的琥珀金"一眼可分，不会搞混现在看的是哪个方向。
- **提示词富文本编辑器**：`<Picture N>` 显示成带缩略图的芯片（鼠标悬停出大图）、
  `<d>[Chinese] …</d>` 显示成对话块（按说话人着色）、`[Shot N]` 显示成镜头徽章、
  六段式标题高亮；`@` 唤起上游素材菜单；「原文 ⇄ 美化」一键切回纯文本。
- **高亮画在节点之上**：ComfyUI 里节点自绘 UI 是真 DOM 元素，canvas 上画的线永远在它下面；
  本包额外挂了一层 DOM 覆盖层，所以高亮不会被资产卡挡住。

### 资产卡Group拆分

- **输出口数量 = 上游实际素材数**：接上一个 `MMX_DIR_GROUP` 后，节点会按「后端真正会打包进去的
  数量」自动开出对应个数的素材口（资产名没写进提示词的卡不算、没选文件的卡也不算，
  与上游同一条规则），上方三个数量控件（`image_count` / `video_count` / `audio_count`）也可以手改。
  **上游一个素材都给不出时就是 0 个素材口**（只留最下面的 `prompt`）——
  这时上游的分组节点自己也会报「至少需要一段提示词，或一组参考图 / 参考音频」。
- **上游变了会自己跟上**：往本节点接线、画布上拖完一条线松手、以及每 600ms 一次的轻扫描
  —— 上游换卡 / 改资产名 / 改提示词 / 加删连线，口数都会跟着变，不用手动干预。
- **已经连出去的口不会因为上游变少而被删**：宁可暂时多留一个口（标题栏补一个 ⚠ 说明
  "口数不是上游原话"），也不会悄悄把下游的线扯掉；等上游再给出这么多、或你手动点
  「按上游刷新」，提示自然消失。
- **状态字写在节点标题栏右侧**，一眼看出"现在的口数是哪来的"：
  标题栏只写数量（`2图 1音` / `固定 9+3+3` / `0 素材`）；
  **接了线但认不出上游**时是琥珀色的 `⚠ 未识别上游`。
  `group` 口**还没接线**时标题栏留白 —— 那是"还没开始"，不是故障。
- **「按上游刷新」按钮只写这四个字**（不背状态）。自动更新没跟上、或想强制重新对账时点它；
  来龙去脉（上游是哪个节点、读写到的数量、认不出的原因 / ⚠ 的原因）会打到浏览器控制台，
  不占界面。
- **固定 9+3+3 开关**：勾上「固定 9+3+3 输出口」后，无论上游几个素材都**一次把口接满**
  （9 图 + 3 视频 + 3 音频 + 1 提示词），以后再换上游就不用动下游连线；
  没用到的口输出空值，挂在它后面的分支会被**静默剪掉**、不报错。
  **关掉时回到打开它之前的数量**（节点会记住那一刻的值，再按上游实际情况修正）。
- **认哪些上游**：① `资产卡镜头打包` 的 `group` 输出（主力）；
  ② 官方 `ref_image_N` / `ref_audio_N` 这类逐口接线节点（按已连线的口数算）；
  ③ `Groups Combine`（**只算第一个分组**，与后端 `as_group` 口径一致）；
  ④ 中间隔了一层 Reroute 之类的中转节点也能穿过去认。
  四种都认不出来时不猜、保留现有口数并亮 ⚠。
- **prompt 口固定在最后**：素材口怎么增删，它的下标都不动，断开再接不用重连。
- **只拆不判**：本节点不做过滤之外的任何改写 —— 编号顺序、素材内容与上游分组完全一致，
  过滤规则也只在「资产名没出现在提示词里」这一条上与上游对齐（这是后端本来就有的行为）。
- **纯搬运，不吃显存**：素材只是从分组字典里取出来原样递下去，不复制、不转码。

### 资产卡任务台

**它解决什么**：多段视频共用同一条「拆分 → 参考生成 → 采样」链。N 段各自的
「资产卡镜头打包」全接到任务台，任务台的下游只接一次线；点一下面板上的「▶ 运行」，
N 段按面板顺序**一段段依次跑完**。想加第 7 段？再接一个打包节点就行 ——
下游一根线都不用动。

```text
                 ┌── 打包 A ──┐
                 ├── 打包 B ──┤      ┌──────────┐   ┌──────────┐   ┌────────┐
  资产卡 ──…──►  ├── 打包 C ──┼──►   │ 任务台   ├─► │ Group拆分├─► │ 参考生成│─► 采样 ─► …
                 └── 打包 D ──┘      └──────────┘   └──────────┘   └────────┘
                                      按运行段选一段      口数固定 9+3+3
```

- **段数不限**：分段口**接一个长一个**（接满最后一个空口就自动多出一个空口），
  不用提前开够接口；尾部没用到的空口会自动收掉，**已经连上线的口任何情况下都不会删**。
- **排序 = 运行先后**：面板里拖动每一段改的是**提交顺序**，
  **不动任何一根连线**（段号 `group_k` 才是接线口径，面板上每行都标着它）。
- **逐段勾「运行」**：不勾的段一根线都不动，只是这次不提交 ——
  跑过的、没问题的段可以留着不出力，只跑改过提示词的那几段。
- **逐段二采开关**：提交时写给下游采样器的 `run_refine`。
  画布上那个控件的值**不会被改**，改的是提交出去的那份任务 ——
  所以「二采开关是下游节点上的普通控件、物理上连不了线」这件事不再是障碍。
- **逐段缓存隔离**：每段的缓存名 = 采样器「缓存命名」的值 + `_s{打包节点号}`。
  ⚠️ 必须隔离：SelfLift 的一采缓存指纹只算 种子/步数/缩放/cfg/形状，**不含提示词** ——
  不隔离的话第 2 段会直接命中第 1 段的一采缓存，成片变成第 1 段的内容（静默串味）。
  用**打包节点号**而不是面板序号当后缀：序号会随排序变，节点号才是这一段的身份。
  面板每 3 秒问一次后端，直接显示每段的「无缓存 / 缓存 N 份」和最近一次的执行状态。
- **每段一眼看清**：段号、上游打包节点号、时长、图/音数量、前 3 张参考图缩略图、二采开关、
  一采缓存状态、以及本次排队状态（排队中 / 运行中 / 完成 / 失败）。
  缩略图做了省资源的处理：每段最多 3 张、34px 小图、`loading="lazy"`、
  服务端按 `preview=webp;45` 转小、URL 不带时间戳所以浏览器能一直缓存住。
- **队列状态看得见**：「▶ 运行」一次性把勾上的段排进队列（ComfyUI 自己的队列本来就是串行的），
  每段跑完把「完成 / 失败」写回行上；「■ 停」中断当前段并撤掉本次还没跑的段
  （只撤自己排的，不动你手动排的队列项）。
- **跑之前会拦住明显跑不通的段**：参考图超 9 张、提示词与素材都空 —— 这两类行会标红、
  且**不会被提交**（否则一段坏卡会把整轮都带崩）。
- **⚠️ 两个必须注意的点**
  1. **下游「资产卡Group拆分」请打开「固定 9+3+3」**。各段素材数不一样，口数固定住
     上下游才不会错位（关着的话，拆分会按"第 1 段"的口数开，跑别的段就串位）。
     任务台面板和拆分节点的标题栏都会为这件事亮 ⚠。
  2. **画布上一次只留最后跑完的那一段**。整张图只有一个保存口 ——
     前面几段的成片在输出目录里、靠文件名区分。这是静态图的物理限制，绕不过去。
- **节点上那个「运行段」控件**：平时不用管（面板会自动按段改写它）。
  想用 ComfyUI 原生的「队列」按钮手动跑某一段时，它就是"跑第几段"的开关。
- **跟原生工作流的关系**：不用任务台时，一个打包接一个拆分，行为与以前完全一样；
  任务台是**可选的加法**，删掉它、把拆分接回任意一个打包即可回到老样子。

### SelfLift Sampler DN

**它解决什么**：兄弟包 `comfyui-SelfLift` 的原节点把「低分辨率前缀 → 提升 → 全分辨率收尾」
写死在**一次**函数调用里，没法"只跑前缀、存盘、回头再收尾"。本节点在接缝处
（原函数 `low_timer.finish()` 那一行）把它**忠实拆成两半**，中间用缓存文件接上。

![SelfLift Sampler DN](<assets/SelfLift节点可拆分一二采可缓存.jpg>)

| 二采开关 | 行为 |
|---|---|
| **关**（一采） | 只跑低分辨率前缀（`transition_step` 步）→ 有「缓存命名」就落盘 → 输出一采 latent |
| **开** + 命中缓存 | 读缓存 → **只跑二采**（提升 + 全分辨率收尾）→ 输出 latent |
| **开** + 未命中 | 先跑一采（落盘）→ 接着跑二采 → 输出 latent |

- **一采缓存**：`<ComfyUI 输出目录>/selflift_cache/<缓存命名>__<指纹>.pt`。
  指纹只算 **种子 / `transition_step` / 低分辨率缩放 / cfg / latent 尺寸** ——
  **不含提示词**。所以换提示词、换模型要改「缓存命名」来隔离，
  否则会直接复用旧的一采（命中时底部状态条会写「跳过一采」）。
- **节点底部状态条**：直接显示"命中几份缓存 / 这次跳没跳过一采"。
  后端把状态放进 `ui.dn_selflift_status`，前端 `onExecuted` 取出来画。
- **「高级选项」折叠**：`cfg / rho / w_min / w_max / 时间分块放大 / 高分辨率分块 / 放大后卸载`
  默认收起。**只折叠右侧控件，左侧接线口一个都不动**（折叠接线口就没法连线了）。
  没用后端 `"advanced": True` —— 那个标记只在 Nodes 2.0 显示展开按钮，
  普通 litegraph 模式下参数会被藏死；本实现两种模式都生效。
- **输出**：`latent` + `状态`（STRING）。关二采时可以只接 `状态`、`latent` 空着 ——
  节点标了 `OUTPUT_NODE`，不会被当成"没被用到"剪掉，缓存照样写。
- **包加载期零副作用**：顶层不 import `torch` / `comfy.*` / 引擎子模块，全部惰性到首次执行；
  否则在 SimpAI 那种 PyInstaller 打包环境里包加载就炸、节点根本注册不进去。
- **⚠️ 和「资产卡任务台」的配合**：任务台提交每一段时会改写本节点的 `run_refine`
  与 `cache_name`（改的是**提交出去的那份快照**，画布上的控件一个字都不动），
  所以多段共用同一条链时，每一段的二采开关和缓存名都是各自独立的。

### 替换这张卡

连线圆点菜单 →「**替换这张卡…**」：搜索栏 + 卡列表（缩略图 / 资产名 / 图·音组成 / 文件名），
列出工作流里**除本组已连之外**的所有资产卡；鼠标悬停看大图，点一下就换。

![替换这张卡](<assets/替换这张卡.png>)

- **同名换源**（重截图、换更好的参考图）：只换连线，提示词一个字不动。
- **换角色**（资产名也变）：先弹确认框，逐条列出「提示词将替换 N 处『旧名 → 新名』」的上下文、
  编号变化（`<Audio 2>` → `<Audio 1>` 这类）、以及警告（如新卡没有音频、
  旧卡的 `<Audio 2>` 将失去对应物）。三个出口：**替换并改提示词** / **只换连线** / 取消。
- **多组联动**：同一张卡还连在别的组里时，确认框多一个复选框
  「同时替换其它组里的同一张卡（N 处，各自改提示词）」—— 每个组的提示词各自重写；
  已经连着新卡的组自动跳过（否则会被去重逻辑静默丢线）。
- **可撤销**：换完的提示条带「撤销」，连线与提示词作为**同一个快照**一起还原。
- 编号重映射按「引用还是那个角色的素材」算，并且是对着**改名后的最终状态**算 ——
  换了角色后新卡会被计入编号，不会把不该动的 token 也改掉。

### 顺手修的一个导演台问题

`dn_continuity_guard.js`：导演台在重建外接组片段时会丢掉每段的 `continuityFromPrev`
（导致「引用上段」被静默改回开启、并连带二采缓存失效）。本扩展只在前端补回该字段，
**不修改导演台源码**。相关分析见
[AIMixer/ComfyUI_MiniMaxH3_Director#198](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/issues/198)。

- **v1.7.8**（2026-10-15）
  - 修「**升采样长时间卡住 / 突然慢几十倍**」（SelfLift Sampler DN 的「高分辨率提升」）。
    症状：同一段升采样平时 11 秒，某些时候变 650 秒，甚至彻底卡死 ——
    日志停在 `Model LatentResizer3D prepared for dynamic VRAM loading` 之后再无输出，
    任务管理器里 **GPU 占用 100% 但功耗只有 80W、温度 40℃**（看着满载其实没在算），
    整个系统发卡。用 `py-spy` 抓栈可以看到进程根本没在算，而是停在
    cuBLASLt 的 dynamic-shader 初始化里等驱动锁。
    原因：这一步要的是**空闲**显存，而 ComfyUI 的动态 VRAM 管理层在显存吃紧时
    不会主动卸载已常驻的大模型（日志里的 `0 models unloaded.`）。典型现场是
    文本编码器（qwen3vl_32b，约 25.8 GiB）还常驻在 32 GiB 显存上，升采样开始时
    只剩 0.5 GiB 空闲 —— 权重只能在「显存 ↔ 主机缓冲」之间反复倒腾，吞吐直接崩。
    修法：`selflift_cache.py` 里升采样前先读**真实**空闲显存
    （`torch.cuda.mem_get_info`，ComfyUI 自己的 `get_free_memory` 在动态模式下会高估），
    低于估算值 ×1.15 就 `unload_all_models()` + `soft_empty_cache()` 腾干净再升采样。
    升采样跑完下游会按需重新加载模型，代价远小于 650 秒的空转。
    （`*.py` 改动**需要重启一次 ComfyUI** 才生效。）
